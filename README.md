# Agent Eval Playbook

**评测集不是项目做完后的验收单，是项目开始时的设计文档。**

这是一个方法论仓库（建设中）。记录我怎么给 Agent / Skill 建评测集、怎么做 BadCase 归因、怎么用回归记录驱动迭代。具体分数会在真实跑完后回填——**没跑出来的数字不会写在这里。**

## 为什么评测是第一步

一个说不清「怎么算好」的 Agent，只能靠演示时的观感判断。评测集把三件事固定下来：

1. **输入长什么样** — 真实分布，不是挑过的漂亮样例
2. **什么叫对** — 评分口径可复现，换个人也能判
3. **错了之后怎么分类** — 才能知道下一步改哪里

面试里被追问时也靠这个：80 条测试怎么来的、判对多少、漏判的是什么、误判的是什么、单条成本多少。讲不出这些，Demo 再漂亮也等于没做过。

## 评测集怎么构造

### 输入来源分层

- **真实场景出现过的输入**（最高优先级）
- **边界情况**：信息缺失、约束冲突、超出能力范围
- **已知坑位**：来自实际返工记录的失败模式

### 每条 case 标注

`输入 / 预期输出 / 评分口径 / 是否在能力边界内`

**边界外的 case 单独成组。** Agent 拒绝执行或转人工是正确行为，不该算作失败——这组专门用来验证「会不会乱接活」。

### 迭代纪律

- V1 → V2 → V3 **每轮只改一个变量**，否则不知道分数变化来自哪里
- 每轮保留完整回归记录，**包括变差的 case**
- 分数提升但边界外误判增加，视为退步

## BadCase 归因

见 [`templates/badcase-taxonomy.md`](templates/badcase-taxonomy.md)。

**归因比分数重要。** 分数只告诉你「有问题」，归因告诉你「改哪里」。
